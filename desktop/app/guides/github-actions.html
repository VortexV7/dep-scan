GitHub Actions Setup

Scan your Maven or npm project automatically on every push and pull request.

Current project folder: loading…

1What DepScan does in GitHub Actions

  • Scans on every push and pull request to main, plus once a week (Monday 06:00 UTC).
  • Reachable vulnerabilities fail the build — a dependency your code actually calls, with a known CVE, blocks the merge.
  • Unreachable vulnerabilities are still reported as warnings, never hidden.
  • Results appear as annotations on the exact file and line in the pull request, as a SARIF report in Security → Code scanning, and as a summary table on the workflow run.

2Add the workflow file

Create this file in your repository: .github/workflows/depscan.yml

# Sample workflow: scan your project with DepScan on every push / PR
# and weekly. Copy this file into your own repo's .github/workflows/.
# Requires: DepScan 0.5.0 release jar (see action.yml), GitHub code scanning
# permission for the SARIF upload.
name: DepScan

on:
  push:
    branches: [main]
  pull_request:
  schedule:
    - cron: '0 6 * * 1' # weekly, Monday 06:00 UTC

permissions:
  contents: read
  security-events: write # needed for upload-sarif to code scanning
  actions: read

jobs:
  depscan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          java-version: '17'
          distribution: 'temurin'
      - name: Download DepScan
        run: |
          curl -sL -o dep-scan.jar \
            "https://github.com/VortexV7/dep-scan/releases/download/v0.5.0/dep-scan-0.5.0.jar"
      - name: Scan (SARIF + text report)
        run: |
          java -jar dep-scan.jar scan . --format sarif --fail-on critical --out depscan.sarif || echo "scan-exit=$?"
          java -jar dep-scan.jar scan . --fail-on critical --out depscan-report.txt || true
          # The first scan's exit code is the real gate: re-run it as the
          # failing step so the job fails only on reachable vulnerabilities.
          java -jar dep-scan.jar scan . --fail-on critical
      - name: Upload SARIF to code scanning
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: depscan.sarif
      - name: Upload reports
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: depscan-reports
          path: |
            depscan.sarif
            depscan-report.txt
Note: the sample downloads the DepScan v0.5.0 release jar. If a newer DepScan release exists, update the version number in the download URL to match.

Or let the app write it for you — click Add to this project at the top of this page. It writes the file into the project folder currently open in DepScan Desktop.

3Push and watch it run

  1. Commit the file and push to GitHub: git add .github/workflows/depscan.yml && git commit -m "Add DepScan security scan" && git push
  2. Open your repository → Actions tab → the DepScan workflow run.
  3. When it finishes, open the run to see the Markdown summary table of findings.

4Where to see the results

  • Pull request files: reachable findings show as ::error annotations on the exact file and line; unreachable ones as ::warning.
  • Security → Code scanning alerts: the uploaded depscan.sarif appears here as code-scanning alerts.
  • Actions run → Summary: a table of every finding (package, version, advisory, severity, location).
  • Artifacts: the depscan-reports artifact holds depscan.sarif and the text report.

5Exit codes — what passes and what fails

Exit codeMeaningBuild result
0No reachable vulnerabilitiesPass
1A reachable (CRITICAL) vulnerability was foundFail
2Usage or configuration error (e.g. no pom.xml / package.json)Fail
3Network error and no cached OSV dataFail

The workflow uses --fail-on critical, so only reachable findings fail the build. Change it to --fail-on none to report without ever failing.
