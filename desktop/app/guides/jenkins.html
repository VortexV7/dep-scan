1What DepScan does in Jenkins

  • A Pipeline job checks out your repository and runs DepScan on it.
  • Reachable vulnerabilities fail the build — a dependency your code actually calls, with a known CVE, turns the build red.
  • Unreachable vulnerabilities are still reported in the log and the HTML report, never hidden.
  • The SARIF report and the HTML report are archived as build artifacts, so you can download them from any build.

2Add the Jenkinsfile

Create this file in the root of your repository: Jenkinsfile

// Sample Jenkins pipeline: scan with DepScan (Stage 3). Copy into your repo root.
// DepScan auto-detects JENKINS_URL and switches to plain logs.
pipeline {
    agent any
    tools {
        jdk 'jdk17'
    }
    stages {
        stage('Download DepScan') {
            steps {
                sh 'curl -sL -o dep-scan.jar "https://github.com/VortexV7/dep-scan/releases/download/v0.5.0/dep-scan-0.5.0.jar"'
            }
        }
        stage('Scan') {
            steps {
                // Exit code 1 fails the build only when --fail-on is breached.
                sh 'java -jar dep-scan.jar scan . --format sarif --fail-on critical --out depscan.sarif'
                sh 'java -jar dep-scan.jar report . --format html --out depscan-report.html'
            }
        }
    }
    post {
        always {
            archiveArtifacts artifacts: 'depscan.sarif, depscan-report.html', allowEmptyArchive: true
            // If the Warnings Next Generation plugin is installed, it can
            // parse depscan.sarif as a SARIF report.
        }
    }
}
Important: the pipeline uses a JDK tool named jdk17. In Jenkins go to Manage Jenkins → Tools → JDK installations and make sure a JDK 17+ installation exists with the name jdk17 (or edit the name in the file to match yours). The sample downloads the DepScan v0.5.0 release jar — update the version in the URL if a newer release exists.

Or let the app write it for you — click Add to this project at the top of this page. It writes the file into the project folder currently open in DepScan Desktop.

3Create the Pipeline job

  1. In Jenkins: New Item → Pipeline, give it a name, click OK.
  2. Under Pipeline → Definition choose Pipeline script from SCM.
  3. Choose Git, enter your repository URL and credentials, set the branch (usually main).
  4. Leave Script Path as Jenkinsfile and save.
  5. Click Build Now. Jenkins checks out the repo, finds the Jenkinsfile, and runs the scan.

4Where to see the results

  • Console Output: the full DepScan report — each finding with package, version, advisory ID, severity and file:line location.
  • Build Artifacts: depscan.sarif and depscan-report.html are archived on every build — open the HTML report right in Jenkins.
  • Build status: red when a reachable vulnerability is found (exit code 1), green when clean.
  • If the Warnings Next Generation plugin is installed, it can parse depscan.sarif as a SARIF report.

5Exit codes — what passes and what fails

Exit codeMeaningBuild result
0No reachable vulnerabilitiesPass
1A reachable (CRITICAL) vulnerability was foundFail
2Usage or configuration error (e.g. no pom.xml / package.json)Fail
3Network error and no cached OSV dataFail

DepScan auto-detects Jenkins (via JENKINS_URL) and switches to plain, colour-free logs that read cleanly in the Jenkins console.
